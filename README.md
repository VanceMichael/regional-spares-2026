# 区域备件服务卡的售后证据采集

这里的资料由本地来源模拟器提供，编号、参与方和历史业务记录全部为合成数据。运行环境为 Node.js 22.23.4，监听地址默认为 `127.0.0.1:8700`，可用 `PORT` 调整端口。

```sh
npm run source
```

另开终端运行 `npm test` 可检查来源契约。测试以独立临时端口启动来源。

两版业务记录和取件字段见 [资料格式](source/formats.md)。`POST /control?edition=r2` 模拟业务方更换当期资料，切回 `r1` 可重新查看初始来源。

本地演练还提供单独的外部接口。用 `npm run provider` 启动，默认地址为 `http://127.0.0.1:8701`，可用 `PROVIDER_PORT` 调整。来源语义、操作回执和演练档见[外部接口](source/provider.md)。

## 采集服务

门店提交维修请求后，由采集服务找回真正的工厂批次和旧工单凭据，形成能办的备件服务卡。先启动来源和外部接口，再用 `npm run service` 启动，默认地址为 `http://127.0.0.1:8720`，可用 `PORT`、`SOURCE_URL`、`PROVIDER_URL` 调整，`NOW_DAY` 可固定业务日（默认取申请日最大值）。

- `POST /collect` 执行一轮采集：按资料版隔离领取来源记录（带条件请求与逐页），核对厂家归档与交接凭据，评估服务卡并对账仓储预留。
- `GET /cards` 列出服务卡明细，`?filed=true|false` 过滤已办与未办；`GET /cards/{申请号}` 查看单卡。
- `GET /handover` 给出可交接的件和仓号；`GET /unfiled` 给出未办原因。
- `GET /audits` 列出核查单：已出库件遇迟到闭单使额度用尽时，显示仍占哪份旧维修权。
- `GET /refetch` 列出继承边更正后应重新取的凭据与服务卡。
- `GET /stock` 给出最近一次看到的仓库存量分布。

规则要点：可办种类只看销售地授权，不能用仓库所在地顶替；换件链上已消耗的次数跟着实物权利，互不继承的同号件各管各的；旧闭单效力无法确认前先标待查，不当作余额可用；预留只对仓、到期时刻和具体服务卡有效，过期预留号不得转给另一家；未出库的预留可释放并让另一张合法的卡承接，已出库的留核查单。
